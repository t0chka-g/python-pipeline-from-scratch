## Часть 1. Создаём проект своими руками

Следующие шаги предназначены для **новой пустой папки**. Если вы уже клонировали этот репозиторий, не создавайте его заново и не заменяйте файлы: откройте терминал в его корне и выполните шаги 4–6, установив зависимость из имеющегося файла командой `python -m pip install -r requirements.txt` вместо установки из шага 6. Затем перейдите к шагу 11 и части 2. В Windows вместо `python` можно использовать `py`, если он доступен; при активированном окружении приведённые ниже команды используют именно его Python.

### 1. Проверяем инструменты

Откройте PowerShell в Windows или терминал в Linux/macOS. Проверьте, что Python и Git доступны:

Windows:

```powershell
py --version
git --version
```

Linux/macOS:

```bash
python3 --version
git --version
```

Ожидаются номера версий Python 3 и Git. Если команда не найдена, см. раздел Troubleshooting. Текстовый редактор нужен, чтобы создавать файлы с указанными именами; используйте обычный текст, а не форматированный документ.

### 2. Создаём каталог

В терминале перейдите в место для учебных проектов, затем выполните одинаковые для обеих систем команды:

```text
mkdir python-pipeline-practice
cd python-pipeline-practice
```

Созданный каталог станет корнем проекта: отсюда выполняются последующие команды. Ожидаемый результат — новая пустая папка и переход в неё. Если имя уже занято, выберите другое.

### 3. Инициализируем Git

```bash
git init
git status
```

Git создаёт скрытый каталог `.git` и начинает отслеживать историю проекта. `git status` покажет новую ветку без коммитов. Имя ветки зависит от настроек Git. Подробности — в части 3.

### 4. Создаём виртуальное окружение

Python-проект — это код и сопутствующие файлы, нужные для его запуска. Виртуальное окружение хранит установленные библиотеки отдельно от других проектов. Создайте его в корне проекта:

Windows:

```powershell
py -m venv .venv
```

Linux/macOS:

```bash
python3 -m venv .venv
```

После выполнения появится папка `.venv`. Она может быть скрыта в файловом менеджере.

### 5. Активируем окружение

Активация направляет команды `python` и `pip` на окружение проекта. В том же терминале:

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Обычно в начале приглашения появится `(.venv)`. Если PowerShell блокирует скрипт, см. Troubleshooting. После работы в активированном терминале команда `deactivate` отключает окружение.

### 6. Устанавливаем Requests

Requests — внешняя библиотека (зависимость), которая помогает отправлять HTTP-запросы. В активированном окружении выполните:

```bash
python -m pip install requests==2.32.5
```

Ожидается сообщение об успешной установке. Версия указана явно, чтобы использовать ту же версию Requests, что и в проекте; его собственные зависимости установятся автоматически. Команда `python -m pip` запускает установщик именно выбранного Python.

### 7. Создаём файлы зависимостей и исключений

В текстовом редакторе создайте в корне `requirements.txt` с содержимым:

```text
requests==2.32.5
```

Он позволяет позже установить зависимость командой `python -m pip install -r requirements.txt`. Теперь создайте рядом файл с точным именем `.gitignore`:

```gitignore
.venv/
__pycache__/
*.py[cod]
data/raw/
```

Он говорит Git не предлагать к добавлению окружение, кеш и скачанные данные. Убедитесь, что редактор не добавил расширение `.txt` к имени `.gitignore`. Проверка `git status` должна показать эти файлы, но не содержимое `.venv`.

### 8–10. Пишем скрипт, запрос и сохранение

Создайте в корне папку `src`: `mkdir src`. В редакторе создайте файл `src/main.py` и введите следующий код целиком, сохраняя отступы из четырёх пробелов. Он отправляет GET-запрос, проверяет ответ и сохраняет его тело. Ниже мы разберём каждую часть.

```python
from pathlib import Path
import sys

import requests


URL = "https://books.toscrape.com/"
OUTPUT = Path(__file__).resolve().parent.parent / "data" / "raw" / "books.html"


def main():
    try:
        response = requests.get(URL, timeout=10)
        response.raise_for_status()
        OUTPUT.parent.mkdir(parents=True, exist_ok=True)
        OUTPUT.write_bytes(response.content)
    except requests.exceptions.Timeout:
        print("Ошибка: сайт не ответил вовремя.", file=sys.stderr)
        return 1
    except requests.exceptions.HTTPError as error:
        print(f"Ошибка HTTP: {error}", file=sys.stderr)
        return 1
    except requests.exceptions.RequestException as error:
        print(f"Ошибка сети: {error}", file=sys.stderr)
        return 1
    except OSError as error:
        print(f"Не удалось сохранить файл: {error}", file=sys.stderr)
        return 1

    print(f"Готово: HTML сохранён в {OUTPUT}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

Ожидаемая структура теперь включает `.gitignore`, `requirements.txt` и `src/main.py`; `.venv` создана локально. В учебном репозитории также есть `README.md` с описанием и папка `docs` с этим уроком.

### 11. Запускаем и проверяем

В активированном окружении из корня проекта:

```bash
python src/main.py
```

При успехе появится сообщение `Готово: HTML сохранён в .../data/raw/books.html`. Откройте этот файл в редакторе: внутри должны быть теги HTML и текст `Books to Scrape`. Это исходный код страницы, а не таблица книг. Запустите команду ещё раз: программа повторно скачает страницу и перезапишет файл. Если появилась ошибка, обратитесь к Troubleshooting; старый файл не доказывает успех последнего запуска.

## Часть 2. Разбираемся в коде

### Путь данных и HTTP

```text
Пользователь → Python → HTTP-запрос → веб-сервер → HTML-ответ → файл
```

Пользователь запускает программу. Python выступает **клиентом**: отправляет запрос серверу сайта. HTTP — правила обмена запросами и ответами; URL `https://books.toscrape.com/` — адрес страницы, а HTTPS защищает соединение. HTTP-метод указывает действие: GET запрашивает ресурс; например, POST обычно отправляет данные. Здесь используется только GET.

Ответ состоит из статус-кода, заголовков с дополнительной информацией и тела. Тело здесь — HTML, текстовая разметка страницы. Код 200 означает успешный ответ, 404 — ресурс не найден, 500 — ошибка сервера. Статус важно проверить до сохранения, чтобы не принять сообщение об ошибке за страницу.

### Импорт, значения и пути

`from pathlib import Path` импортирует средство для работы с путями, `import sys` — средства взаимодействия с Python, включая завершение программы и вывод ошибок. Оба входят в стандартную библиотеку Python. `import requests` подключает отдельно установленную библиотеку. `import` делает имена из модуля доступными в коде.

`URL = "..."` присваивает переменной URL значение типа `str` (строку). Переменная — имя, с которым связано значение. `OUTPUT` содержит объект `Path` — представление пути. `__file__` указывает на файл программы, `resolve()` превращает его в абсолютный путь, а два `.parent` поднимаются из файла в `src`, затем в корень проекта. Оператор `/` у `Path` присоединяет части пути; результат указывает на `data/raw/books.html` независимо от текущей папки терминала.

### Функция и запрос

`def main():` объявляет функцию — именованный набор действий. Тело функции записано с отступом. Вызов `requests.get(URL, timeout=10)` передаёт функции аргументы: адрес и именованный параметр `timeout`. Она возвращает объект `Response`, который сохраняется в переменной `response`. Объект объединяет данные и действия над ними: например, `response.status_code` содержит число статуса, `response.content` — байты тела, а `response.raise_for_status()` проверяет статус и вызывает исключение для 4xx и 5xx.

`timeout=10` ограничивает ожидание сетевых операций в секундах, чтобы не ждать бесконечно; это не общий лимит времени всей загрузки. Проверка `raise_for_status()` стоит до записи файла. Requests обычно следует перенаправлениям автоматически; проверяется итоговый ответ.

### Ошибки и сохранение

`try` начинает блок, в котором возможна ошибка. `except` перехватывает соответствующее исключение — сигнал о возникшей проблеме. `Timeout` означает таймаут, `HTTPError` — неуспешный HTTP-статус, `RequestException` охватывает другие ошибки Requests, включая проблемы подключения. `as error` сохраняет описание ошибки в переменную. `OSError` обрабатывает ошибки файловой системы. Более конкретные исключения указаны перед общим.

`OUTPUT.parent.mkdir(parents=True, exist_ok=True)` создаёт родительские папки, включая недостающие; существующая папка не вызовет ошибку. `OUTPUT.write_bytes(response.content)` записывает полученные байты без преобразования кодировки. При повторном успешном запуске файл перезаписывается. Старая копия остаётся при ошибке сети до записи; ошибка во время записи может оставить неполный файл.

`print` выводит сообщение. В строке `f"...{error}..."` значение переменной подставляется вместо фигурных скобок. `file=sys.stderr` направляет сообщение в стандартный поток ошибок. `return 1` завершает функцию с кодом ошибки; после успешной записи `return 0` означает успех. `if __name__ == "__main__":` проверяет, что файл запущен как программа, а `sys.exit(main())` вызывает функцию и передаёт её код завершения операционной системе.

## Часть 3. Git на практике

Git-репозиторий — каталог проекта с историей в `.git`. Рабочая директория — файлы, которые вы сейчас редактируете. Коммит — сохранённый снимок добавленных в индекс изменений; история — последовательность таких снимков. Индекс (staging area) — список подготовленных к коммиту изменений.

### Если вы создали проект с нуля

Вы уже выполнили `git init`. Посмотрите изменения, подготовьте только созданные исходные файлы и зафиксируйте их:

```bash
git status
git add .gitignore requirements.txt src/main.py
git diff --cached
git commit -m "lesson 01: create Python project and fetch HTML with Requests"
git log --oneline
```

`git status` показывает состояние, `git add` помещает файлы в индекс, `git diff --cached` показывает подготовленное, `git commit` создаёт снимок, а `git log --oneline` показывает историю. Если Git просит имя и email, настройте их для этого репозитория командой `git config user.name "Ваше имя"` и `git config user.email "you@example.com"`, затем повторите коммит. `.gitignore` не удаляет уже отслеживаемые файлы: его стоит создать до `git add`.

### Если репозиторий уже клонирован

`git init` и первоначальный коммит не нужны: история уже получена при клонировании. Из корня проекта выполните:

```bash
git status
git log --oneline
git diff
```

`git diff` показывает ещё не подготовленные изменения отслеживаемых файлов; новые файлы видны в `git status`. После редактирования используйте `git add <путь>`, `git diff --cached` и `git commit -m "описание"`, если хотите сохранить свою работу. Не добавляйте чужие изменения без проверки.

### Изучаем прошлый коммит безопасно

Скопируйте нужный хеш из `git log --oneline`. `git show <хеш>` покажет коммит и его изменения, не меняя файлы. Чтобы открыть весь снимок в отдельной соседней папке, выполните из корня репозитория, подставив реальный хеш без угловых скобок:

```bash
git worktree add --detach ../lesson-snapshot <хеш>
```

Git создаст отдельную рабочую директорию в состоянии выбранного коммита; текущие файлы и ветка сохранятся. Папка `../lesson-snapshot` не должна существовать заранее. Просмотрите снимок и вернитесь в основной каталог. Если в снимке нет нужных изменений, удалить которые было бы жалко, удалите его через `git worktree remove ../lesson-snapshot`. При несохранённых изменениях Git может отказаться удалять папку: сначала сохраните нужное. Не используйте `reset` для этой задачи.

## Часть 4. Закрепление материала

Работайте на своей копии и проверяйте `git diff` после изменений.

1. **Другая страница.** Условие: замените URL на `https://books.toscrape.com/catalogue/page-2.html` и скачайте её. Подсказка: измените значение `URL`. Ожидается HTML второй страницы каталога. Критерии: программа сообщает об успехе, а в файле есть текст `Page 2 of` и HTML-теги.
2. **Статус и размер.** Условие: добавьте вывод HTTP-статуса и размера полученного файла в байтах. Подсказка: используйте `response.status_code` и длину `response.content`. 3. **Адрес из командной строки.** Условие: передавайте URL при запуске программы аргументом. Подсказка: изучите `sys.argv` и проверьте, передан ли аргумент, прежде чем обращаться к нему. Ожидается запуск вида `python src/main.py https://books.toscrape.com/`. Критерии: указанный адрес загружается, а при отсутствии аргумента выводится понятная инструкция вместо ошибки индекса; обработка сетевых ошибок сохранена.

## Troubleshooting

| Симптом | Вероятная причина | Что сделать |
| --- | --- | --- |
| `python3`, `py` или `python` не найден | Python не установлен или команда отсутствует в PATH — списке каталогов поиска команд. | Установите Python 3 с [python.org](https://www.python.org/downloads/), на Windows включите добавление в PATH; откройте новый терминал и повторите проверку версии. На Windows при наличии `python`, но отсутствии `py`, используйте `python -m venv .venv`. |
| Активация PowerShell запрещена | Политика выполнения блокирует `Activate.ps1`. | Не меняя политику, используйте ` .\.venv\Scripts\python.exe -m pip install -r requirements.txt` и ` .\.venv\Scripts\python.exe src/main.py` из корня; начальные пробелы не обязательны. В Linux/macOS проверьте, что окружение создано и команда `source` выполняется в bash/zsh. |
| `ModuleNotFoundError: No module named 'requests'` | Библиотека установлена в другой Python или не установлена. | Активируйте нужное окружение и выполните `python -m pip install -r requirements.txt`; при отказе от активации используйте полный путь к Python окружения, как выше. |
| Сообщение об ошибке сети или подключения | Нет интернета, сайт недоступен или настройки сети мешают соединению. | Проверьте адрес и откройте сайт в браузере; проверьте подключение и настройки прокси своей сети, затем повторите запуск. |
| Сайт не ответил вовремя | Соединение или сервер отвечает слишком медленно. | Проверьте подключение, повторите позже; при необходимости разумно увеличьте `timeout` и снова запустите программу. |
| HTTP 404 или 500 | Адрес неверен либо сервер сообщил о внутренней ошибке. | При 404 проверьте URL; при 500 повторите позже и проверьте доступность сайта. Не считайте старый HTML результатом неудачного запуска. |
| Ошибка SSL-сертификата в сообщении об ошибке сети | Проблема доверия к сертификату, времени компьютера или настройкам сети. | Проверьте дату и время, обновите Python и сертификаты системы, обратитесь к администратору сети при использовании корпоративного прокси. Не отключайте проверку сертификатов. |
| Ошибка записи или отсутствует `data/raw` | Нет прав на создание папки, путь занят файлом или код создания папки изменён. | Проверьте сообщение и права на каталог проекта, наличие `mkdir` в коде и свободное место. При исправном коде папка создаётся автоматически; не удаляйте чужие файлы ради освобождения пути. |

## Словарь

- **Зависимость** — библиотека, необходимая программе; здесь Requests.
- **Виртуальное окружение** — отдельное место для Python-пакетов проекта.
- **Репозиторий** — проект с историей Git; **коммит** — сохранённый снимок изменений.
- **Клиент / сервер** — программа, отправляющая запрос / система, отвечающая на него.
- **URL** — адрес ресурса; **HTTP** — правила обмена запросами и ответами.
- **Статус-код** — числовой результат HTTP-запроса; **HTML** — разметка веб-страницы.
- **Исключение** — сигнал об ошибке во время выполнения кода.

## Сценарий видеоразбора

Продолжительность — около 6 минут:

1. **0:00–1:00:** показать пустую папку; проверить `python3 --version` и `git --version`, создать каталог и выполнить `git init`.
2. **1:00–2:00:** создать и активировать `.venv`, установить Requests, показать `requirements.txt` и `.gitignore`.
3. **2:00–3:00:** нарисовать путь запроса и объяснить GET, URL, ответ и статус.
4. **3:00–4:30:** показать написание `src/main.py`, разобрать `requests.get`, таймаут, проверку статуса и запись файла.
5. **4:30–5:30:** выполнить `python src/main.py`, открыть HTML и повторить запуск; показать пример диагностики ошибки.
6. **5:30–6:30:** выполнить `git status`, `git add`, `git diff --cached`, `git commit` и `git log --oneline`; назвать три задания для самостоятельной работы.
